# AI Agent Instructions — dots-and-boxes

Purpose

- Use these instructions when editing or generating code, docs, or configuration for this project.
- All base conventions from ai-agent-standards apply unless explicitly overridden below.

Agent Behavior Rules (concrete)
- Do not invent project-specific build steps unless you find explicit files such as `package.json`, `pyproject.toml`, or `Makefile`
- When adding examples or code snippets, prefer small, runnable artifacts and include exact file paths
- If you cannot determine a convention from repository files, ask a clarifying question rather than guessing

Interaction Workflow
- State the overall task before starting work
- Explain each step clearly and concisely
- Describe code changes before implementing them
- Ask for confirmation before applying changes
- Apply changes only after developer confirmation

Commit Message Format
- Format: `type(scope): short summary\n\nBody (optional)\n\nRefs: #<issue>`
- Allowed types: `feat`, `fix`, `chore`, `docs`, `ci`, `style`, `refactor`, `test`
- Example: `feat(parser): add markdown tokenizer`

Documentation Updates
- When code or standards change, update `README.md` and the relevant convention markdown files together

Project-Specific Overrides

None currently defined. Project-specific rules override base standards. Document any overrides here with clear reasoning.
