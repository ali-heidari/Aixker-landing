How AIxKer is Different

Three components combined in a way that existing tools cannot replicate.

XDP Kernel Bypass

An eBPF/XDP program is injected directly into the NIC driver. Traffic is redirected before the Linux TCP/IP stack processes a single byte — no userspace, no socket buffers, no context switches.

RL Decision Engine

Each node runs a local reinforcement learning model that reads CPU, memory, and TCP connection metrics to classify its own state as FREE or BUSY — and decides autonomously when to redirect.

Zero-Config Discovery

Agents find each other via UDP multicast gossip with no central registry, no Kubernetes, no etcd. A new node joins the cluster automatically in seconds.

Connection-Aware NAT

A per-connection 5-tuple NAT table in kernel BPF memory ensures established TCP sessions survive backend changes and peer failures — clients never see a reset.

Self-Healing Failover

Dead peer detection via parallel ICMP probes. On failure, all known FREE peers are pinged concurrently (~50ms total). The first healthy peer is promoted and new SYNs route immediately.

Drop-in Deployment

Each container bundles your backend service with the AIxKer agent. Add one Dockerfile stage, keep your existing service unchanged. No code modifications, no sidecar configs, no proxy rules.

Architecture

Routing decisions happen inside the kernel, before the TCP stack sees each packet.

1

TCP SYN hits the NIC

The XDP hook fires at the driver level before the Linux kernel network stack processes the packet.

2

RL model reads system metrics

The userspace agent feeds CPU load, memory pressure, and connection count into a local neural network that classifies the node as FREE or BUSY.

3

SERVERMAP written to BPF

When the node turns BUSY, the agent picks a FREE peer via multicast gossip and writes the target IP + MAC into the kernel-space SERVERMAP BPF map.

4

XDP_REDIRECT to target node

New SYNs are rewritten (IP, MAC, port) and redirected NIC-to-NIC. A NAT entry is created in kernel memory. Return packets are rewritten back transparently.

// Packet path when node is BUSY
Client SYN → NIC → XDP hook
check SERVERMAP → target found
check NAT_MAP → new connection
insert outbound + inbound NAT entries
rewrite: src IP = local IP
dst IP = target IP
ports = per-CPU ephemeral
XDP_REDIRECT → target NIC

// Return packet path
Target → NIC → XDP hook
NAT_MAP lookup → inbound entry found
rewrite back to original client
XDP_REDIRECT → client

// Peer discovery (background)
UDP multicast 239.255.255.250:9999
"IP,state,MAC" → gossip cache
TTL = 10s, reaper every 5s
dead peer → evict + find next FREE

Where AIxKer
Wins Outright.

nginx and haproxy run in userspace. Every packet crosses the kernel boundary twice and traverses the full TCP/IP stack. At peak load, they saturate and drop requests. AIxKer's XDP hook fires before the kernel even classifies the packet as a socket.

The 3ms median gap between AIxKer and nginx is the measurable cost of those context switches and buffer copies. The 23× p(99) latency gap under stress is what that overhead compounds into at scale.

AIxKer's structural advantage — XDP kernel bypass combined with per-node RL decisions and zero-config multicast peer discovery — does not exist in any other open-source load balancer.
